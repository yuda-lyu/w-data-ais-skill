# 信件往返驗證（email round-trip）：以真實收件匣把「只寫進信裡的東西」接回 e2e

**適用**：產品流程的下一步只能從信件取得輸入（重設後的亂數密碼、驗證連結的識別碼、一次性登入碼），或 spec 要求信件的寄件者／主旨／內文逐字相符、且手冊要呈現「收到的信長什麼樣」。本篇是 SKILL.md §10「email round-trip」列的展開；專案落地（收件匣清單、金鑰檔位置、案例編號）寫在該專案的規則帳本與共用文件，不寫在這裡。

## 1. 先證明三步可行，再擴案例

動手擴 spec 前先各做一次最小探測並留 log：①以 API 建立或列出收件匣；②用產品現行寄信功能寄一封到該收件匣；③以 API 讀回全文並取出要用的值（密碼、連結）。任一步不通就回報，不先寫案例。殷鑑：第一把金鑰對 API 與儀表板皆回 `Forbidden`，探測一分鐘就發現，省掉整批案例白寫。

## 2. 收件匣服務的選擇與配置

- **要 API 可讀全文**：組織層金鑰能列收件匣、讀信件 html/text、建收件匣；只能寄不能收的服務不適用。儀表板多為 OAuth 登入，不可自動化，也不拿它截圖。
- **一位收信者一個收件匣**：以收件匣名對應種子帳號（`{帳號小寫}@…`），display name 用該帳號的顯示名，信件內文的稱呼才對得上。
- **免費方案有每帳號收件匣上限**：不夠時再要一個服務帳號，金鑰檔改成「預設金鑰＋收件匣→金鑰對應表」，取信時依收件匣挑金鑰。子位址（`+`）能省收件匣，但先確認產品的電子郵件檢核放行 `+`，否則種子含 `+` 會讓整張使用者清單每次儲存被擋。
- **金鑰檔**：`test/e2e-secrets.json`（gitignore）＋同構範本 `e2e-secrets.example.json`；缺檔或金鑰無效時涉信案例**直接拋錯**，不 skip、不 pending——靜默略過會讓「收信」這段永遠沒被驗過而測試照綠。
- **種子**：收信者的電子郵件改為收件匣位址。若專案慣例是「密碼即電子郵件」而某帳號的密碼是跨專案共用的標準測試密碼，種子產生器加密碼覆寫表讓密碼不變，並在共用文件記為唯一例外。

## 3. 後端與時鐘

- 涉信案例標 `mail: true`，重置時以真實 SMTP 啟動後端；其餘案例的 SMTP 一律指向拒絕連線的埠（`127.0.0.1:1`），確保只有該等案例會外寄。
- **假時鐘會讓信送不到**：寄信程式庫以無參數 `new Date()` 產 Date 標頭，假時鐘使標頭落在過去，SMTP 回 `250 OK` 但收件匣永遠不出現。在 e2e 後端殼對 `sendMail` 補 `date: new Date(Date.now())`（`Date.now` 未被攔截），不動產品碼。「SMTP 接受」不等於「送達」，寄後一律以收件匣輪詢確認。
- 每次全跑會外寄幾封、月配額多少，寫進規則帳本；信件不刪（收件匣即證據），取信以時間與訊息識別碼過濾。

## 4. 取信與斷言

- `waitMail({ inbox, subject, since, excludeIds })`：每 3 秒輪詢，取主旨相符、時間戳不早於案例起始減 60 秒、且不在 `excludeIds` 內的最新一封，讀全文；120 秒逾時拋錯。
- **同案例同主旨兩封**（申請時一封、重寄一封）：動作前先列既有訊息識別碼，取信時排除，否則抓到第一封而假通過。
- 斷言依 spec〈信件對照〉：寄件者、收件者、主旨逐字；內文 html 轉純文字後逐字比對；隨機部分（密碼、識別碼）以格式斷言並抽出供下一步使用。
- 連結類：斷言起首與結尾（基底網址、`token=`、語系參數），開啟後的結果頁（成功／已驗證／無效）各是一個可觀察終態，各自一張圖；「無效連結」是不需要收信的瀏覽類案例。

## 5. 信件的標準圖

- 不截儀表板。以固定版式的**檢視器頁**在同一 context 另開一頁 `setContent`：收件匣、主旨、寄件者、收件者、內文；**不顯示時間**。紅框框內文整塊。
- 隨機字串換成固定寬度的黑條，讓像素決定性且不洩漏：`<strong>` 內的亂數密碼換 120px 黑條；連結內 `token=` 的值換 220px 黑條並移除 `href`（保留可讀的基底網址與語系參數，讀者看得出這是連結）。
- 手冊敘述寫「隨後於信箱收到寄件者為『…』、主旨為『…』的信，信中…」，不提收件匣服務名稱。

## 6. 自助註冊類流程的額外事項

- 需要設定開關（允許註冊、驗證連結的基底網址）：五份環境設定同步，e2e 設定自正式設定衍生，登入頁自此多出「申請帳號」類連結——凡拍到登入區塊的既有標準圖都受影響，依 §7.9 只重產受影響者並以雜湊回驗其餘未變。
- 自助建立的帳號常缺「登入後轉址」等後台才填的欄位，預設登入會被擋：案例改走不需要該欄位的入口（如使用者資訊頁），並在 spec〈已知落差〉記為設計事實，不改產品。
- 節流（同帳號 N 秒內只能重寄一次）與「申請不記節流」這類細節先讀後端證成，寫進 flow 備註，避免案例順序踩到節流。
