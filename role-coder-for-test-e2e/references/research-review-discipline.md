# 調研紀律、外部複審、業主裁示與反模式

適用於 e2e flake 追根因、baseline 異常、派外部 AI 複審等情境；與 [pixel-mismatch-diagnosis.md](pixel-mismatch-diagnosis.md) 搭配。

## 1. 調研紀律（動手前，不是卡住才做）

- **姊妹專案是第一手證據**：同組織共用同套 UI 組件庫與 e2e 方法論的專案，其 `test/` 註解是已付學費的實驗紀錄。遇截圖不穩第一步用 Grep 掃 `1px|位移|shift|光柵|raster|subpixel|次像素|flake`，姊妹專案一起掃。
- **追組件到底**：從外層往內追每層 template style，直到找到帶 `overflow / transform / transition / 計算寬度` 的那層；外層零命中就停＝錯誤結論。
- **negative results 明文記錄並帶進下一輪**：每個被否證假說記「假說＋實驗＋樣本數＋結果」；派工 / 接手時列「已推翻清單」，否證項與確立項分兩張表各附證據欄。
- **孤立復刻前先問「已知可靠重現器是什麼」**：整檔 mocha 馬拉松穩定 ~10% 中獎，孤立復刻 207+ 發零命中——永遠差「馬拉松的系統狀態」；探查腳本簡化掉 `setLang` / per-case fresh 等步驟就重現不出，復刻不全別下「已 / 未重現」結論，直接 `mocha --grep` 跑真 case。
- **長批次一律 `run_in_background` + Monitor 逐檔訊號**（filter 涵蓋失敗字樣），等待期做不衝突的事（讀組件原始碼、寫認證腳本、盤姊妹專案）。
- **被禁止的方法**：①統計重跑（多跑 N 輪 0 翻面算過）不得作為 e2e 驗證手段，包裝成「N 次 launch 等同統計門檻」也一樣；②放寬容差 / ±1px 位移回退當 pass 條件——吞掉真實 1px 版面回歸；作為 fail-dump 診斷輸出可以（標「疑似 ±1px 剛性位移」），作為放行條件不行。

## 2. 派外部 AI 複審：讀檔權限就是可信度

- 不能自己讀檔＝替你的版本背書。派工前讀該派工技能的 flags 文件；確認套件安裝位置；先以「讀某檔並原文引用第 N 行」探測（含 cwd 外之姊妹專案與 skills 目錄，用 `--add-dir`）；`validate` 要求引用指定內容或格式（中文 `檔案:行號` 亦算），不只驗非空。
- Windows 下讓它用 node 讀 UTF-8 檔（PowerShell `Get-Content` 對中文常亂碼，ConstrainedLanguage 下 `[Console]::OutputEncoding` 被擋）。
- prompt 開放式「前輪觀測只是起點，請自行驗證或推翻」；要求每條標「已驗證（file:line）/ 假說（需實測）」；禁止捏造 flag 名與 file:line；外部設計的實驗規模要對照本地架構（共用單 DB + 單後端跑不動平行 worker）。
- **先審表後審方案**：請它先挑戰輸入空間表 / 遷移對照表 / 契約映射的完整性與屬實性，最後才審方案。收回後逐條核對源碼再採納，不整批接受也不整批駁回，採納 / 駁回逐條附理由。

## 3. 業主裁示過的原則（跨專案適用）

1. **驗證門檻必須確定性**：「不能用統計的方法當 e2e 測試」——改用機制對應的確定性檢查（幾何量測懸出=0、逐位元交叉驗證差 0、全庫認證掃描）。
2. **禁止某手段 ≠ 放棄該問題，裁示範圍不外推**：把「不做逐旗標消融」擅自寫成 ADR「已知不修」被明確糾正；Decision 逐字對應業主原話。
3. **根因要到組件 / 行 / 幾何條件，不推給「渲染問題」**。
4. **模糊比對須先鑑別誤差種類才能開**：容差對應已鑑別的「字形 / SVG 邊緣次像素」；剛性位移是另一種類，必須繼續 fail。
5. **介入性證明**：「先去改 +0 證明就是這 1px，要不然只是亂猜」。
6. **外部複審要能獨立讀檔**。
7. **等待空檔要利用**：「趁空檔去閱讀組件程式碼查嫌疑」。
8. **每個重要流程 × 單語系只 new 一次瀏覽器；換流程或換語系都重新 new**（per-case fresh browser 的原話依據）。
9. **spec 的 description 是「將來直接給使用者操作手冊之用的敘述文字」**，主述是介紹給使用者的引言者，不是指導撰寫 e2e 的要求者；不寫程式碼位置、不寫第幾階段、不用括號補充敘述（「顯示座標軸與網格（尚未載入任何模型）」要改成「顯示座標軸與網格，此時亦尚未載入任何模型」）。且要寫得夠清楚仔細與完整，避免將來還要大改。詳見 [spec-case-format.md](spec-case-format.md) §2。
10. **舊版說明文件不是 spec 的依據，也不是「已知落差」的比對對象**：內容已改動不少的舊文件只供參考，不得把舊資料當成問題然後說要再查證；spec 內禁止提到它。

## 4. 反模式清單（每條都付過代價）

| 反模式 | 代價 | 避免 |
|---|---|---|
| 先讀碼推測後量測 | 一輪 + 誤導方向 | 量測先於任何推測公布 |
| 探查腳本簡化掉真實 case 步驟 | 兩輪重現不出 | 逐步復刻或直接 `mocha --grep` 跑真 case |
| 同 launch 連拍當 n=N | 錯誤反駁正確假說 | launch 級：一 launch 一樣本 |
| 重產當解法 | 一輪 + 錯誤建議 | 先證產圖本身是否確定性 |
| 派外部 AI 沒讀 flags 文件 / 沒探測讀檔 | ~100 分鐘 + 三次 token | 先驗它能否讀檔、能否執行 shell |
| 孤立復刻獵捕異態 | 207+ 發零命中 ~90 分鐘 | 用已知可靠重現器 |
| 診斷 env 下寫正式 baseline | 整輪全套全紅 | 診斷 regen 寫獨立目錄 / env guard；收斂後拆閘門 |
| 憑記憶斷言 baseline 產製條件 | 差點誤指上游回歸 | mtime + LCD 掃描 + 逐位元比 |
| 偵測器未自驗就信輸出 | 兩輪調窗口 | 已知答案樣本先跑；命中印 RGB |
| 選擇器靜默失效 | 四次假「無差異 / timeout」 | computed style、真 import path、命中數斷言、窗口留餘裕 |
| 「禁止某手段」外推成「已知不修」 | 修 ADR | 裁示不外推 |
| 長批次無進度回報 | 業主質問 | 背景跑 + Monitor |
| 發布流程順序錯（e2e 把語系注入 entry HTML 後才產模板） | 重跑 build | build → 產模板 → 打包一氣呵成，驗佔位符數量 |
| 懷疑上游前沒先排除自身污染 | 一輪全套 | 先驗 baseline 與測試端一致 |
| 用錯 cwd 跑 mocha | 整檔「標準圖不存在」假紅 | 以專案根為 cwd；相對路徑由 `projRoot` 解析 |
| ADR 停在「調查中」 | 後人重啟調查 | 根因收斂後補「最終收斂」段並拆診斷閘門 |
| 規則標題只寫「框架跑完不退」 | 同款 hang 一 session 累犯 3 次 | 規則錨定 artifact（「接觸 spawned server 的 script」），觸發來源明列，audit 掃全部同類檔 |
| 寫 e2e 從「最簡單怎麼推進狀態」起手 | 13 case 全 simulate 掩蓋 2 個 production bug | 從「真實使用者會做什麼」起手，6 步 user path + 按鈕全清單 |
| description 寫成測試理由書（「本案例為…之驗證」「含兩階段截圖」「與 E2E-003 成對構成契約」、夾 `file:line`） | 140 條整批退回重寫 + 一輪外部複審 | description 受眾是使用者，寫成手冊引言；技術資訊移到 flow 備註（spec-case-format §2） |
| 改寫 description 時為了文風把權限、入口、送出方式、成功訊息原文一併刪掉 | 二輪複審再補 43 條 | 改寫前先列「必須保留的六問」（spec-case-format §2.4），逐條對照後才交付 |
| 拿舊版說明文件與現況比對寫成「已知落差」 | 13 條落差全數作廢重整 | spec 只認現行程式碼與實機；舊文件不引用、不比對 |
| 沒看 `v-if` 就寫案例 | 6 個 UI 不可達案例（未變更即儲存、未選檔即上傳、無報告即下載…） | 每個操作路徑先追按鈕渲染條件；防禦性提示標「UI 不可達」不設案例 |
| 權限負向案例在初始空畫面執行 | 假通過（按鈕本來就不渲染） | 先把狀態推到有權限者看得到按鈕，再換帳號比對 |
| 採納外部複審「多張表未套後端權限」未核 | 寫進已知落差後被實算 110 張表全覆蓋反證 | 複審每條先對源碼（實算、grep），再採納或駁回並附理由 |
| 案例廢止後順移後續編號 | baseline 檔名、對照表、複審引用全部錯位 | 廢止保留編號，單行註記理由 |
