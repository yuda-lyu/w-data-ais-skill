# 交付驗證與回報：docx 核對法、回報範本、裁示衛生

本檔為 SKILL.md §8 之作法。所有指令以專案根為工作目錄，路徑以佔位表示。

## 1. md 層核對

| 檢核 | 作法 | 判準 |
|---|---|---|
| 節數 | 數 `### ` 標題 | ＝已撰寫案例數 |
| 圖數 | 數圖片標籤（`src="pics/`） | ＝各案例可用圖數之和 |
| 圖題／表題 | 數「圖n 」「表n 」佔位（產 md 時尚未編號者為佔位字樣） | 圖題＝圖數；表題＝節數 |
| 殘留 | grep `{fig:`、未解析之 `{` | 0 |
| 測試字樣 | grep `e2e`、「標準圖」「紅框」「測試」（畫面原文除外） | 0 |

## 2. docx 層核對（不憑回傳值）

1. **實體檔**：存在、時間戳晚於本次 genMd、大小合理（圖多之冊達數十 MB 屬正常）。
2. **抽 `word/document.xml`**（以 zip 工具直接讀，不解壓整包）。
3. **先串接文字節點再計數**：文書格式把一句話拆成多個 `<w:t>`，直接對原始 XML 找「圖1 」會漏；正確作法是取出所有 `<w:t …>…</w:t>` 之內文串成一條字串後再掃：

```
圖題數   = 匹配「圖\d+ 」之數        → 應＝圖數
表題數   = 匹配「表\d+ 」之數        → 應＝節數
圖引用   = 匹配「如圖\d+所示」之數   → 應＝圖數
表引用   = 匹配「如表\d+所示」之數   → 應＝節數
最後圖號 = 最後一個「圖\d+ 」        → 應＝圖數（編號連續之簡易檢查）
大括號   = 匹配「\{[^}]*\}」之數     → 應＝0（只在串接後之文字上掃；原始 XML 內之大括號多為圖片識別碼，不是殘留）
測試字樣 = 匹配「e2e」之數           → 應＝0
```

4. **媒體數**：`word/media/` 內檔案數少於圖數屬轉檔器對相同圖檔去重（同一張圖被兩節引用、或連續相同之兩張圖），版面不受影響，回報時說明數字。
5. **首欄不換行**：抽表格首欄之段落屬性確認 nowrap 類設定存在（或以人工開檔抽查一節）。
6. **殘留行程**：產後列出文書軟體行程，應為空；有殘留即結束並記錄。

## 3. lint 與同步

- 專案 lint 掃描範圍含分冊子夾之 `src/` 與 `report/`；PASS 才交付。
- 為過 lint 或對帳而改動 spec 之 title／description：e2e 測試檔之 `it()` 標題同步改，並跑語法檢查；受影響之冊重跑 genMd → lint → genDocx → 本檔 §1～§2。
- L3 文件之版本紀錄登記本批新增之冊、圖數、新裁定之寫法（數字政策、入口捲動、暫時狀態、英文圖名之處理）。

## 4. 回報範本（五段固定，缺段即不完整）

```
【產出】<冊名>：<節數> 節／<圖數> 張；docx <大小>；路徑 <report/>
【回驗】genMd 零錯；lint PASS；document.xml：圖題/表題/引用皆吻合、無殘留、無測試字樣；媒體去重 <n/m>；無殘留文書行程
【spec 與測試檔改動】<案例>：<原載> → <改為>（依據：圖鍵 <…>）；受影響之冊已重產
【請裁示】（只放業主不決定就無法往下做者；每條寫「不決定則卡在哪一步」）
【知悉】（已依既有原則決定之寫法、非缺陷之畫面實況、規則之自然結果；不需回覆）
```

## 5. 裁示衛生（列「請裁示」前之三問）

1. **業主不決定，我就做不下去嗎？** 能依既有原則（L3 文件、報告總則、本技能）自行決定者，決定後列「知悉」或不提。檔名怎麼描述、筆數怎麼寫、圖名用哪個語意，都屬此類。
2. **之前是否已裁示？** 查 L3 定稿句與版本紀錄、共用文件之裁決表與待裁示彙整、專案記憶；已裁示者一律不重提（如「紅框在紅色按鈕上不可辨，暫不處理」）。
3. **若涉權限，是哪一軸？** 「無畫面權限」與「資料可讀」是兩件事，分開陳述；資料軸依表類別之規則開放者是設計事實，不是裁示項。

常見誤列：連續相同之兩張圖（規則之自然結果）、訊息圖上其他即時數值為載入前狀態（畫面實況）、產物檔名含日期之描述方式（撰寫者依原則決定）、docx 媒體去重（轉檔器行為）。

## 6. 暫停指令之處置

使用者要求「先暫停」「先看 docx」時：列出已可確認之冊與其節／圖數，停止產製新的 docx；已派出之撰寫可在背景續寫 content，但不跑 genDocx；回報時明列「已產」「撰寫中」「未開始」三類。
