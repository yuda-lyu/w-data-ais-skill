# 派工提示骨架、配額與監看、驗收表

主代理把「一個流程的手冊內容」派給子代理時，提示須自足（子代理看不到本技能與對話），下列各段缺一不可。以 `<…>` 為佔位，派工時全部代入絕對路徑與實際值。多流程同批派工時，把「工作流程／圖名規則／敘述規則／守則／回報」抽成一份共用守則檔供全部子代理先讀，提示只留專案與檔案、本流程專屬事項。

## 1. 提示骨架

```
你是報告撰寫者。任務：為「<系統名>之使用者操作手冊」撰寫<瀏覽|編輯>類 E2E-<起>～E2E-<迄> 共 N 個案例之手冊內容（圖名與圖文敘述），<建立新的|寫入既有>內容檔。全程用繁體中文。為避免中途遺失成果，**每寫完 3 個案例就用 Write/Edit 把內容檔存檔一次**（先寫已完成之案例，之後追加），不要等全部寫完才第一次寫檔。

## 專案與檔案（皆為絕對路徑，不要 cd）
- 專案根：<絕對路徑>
- spec（真理源）：<絕對路徑>（先整篇讀完，含「畫面元素對照」「訊息對照」與「已知落差」）
- 標準圖：<絕對路徑>/<流程前綴>-<圖鍵>.png（<寬×高> 截圖，每張恰有一個紅框；共 <張數> 張，與 spec 視覺段逐鍵一致）
- 你要修改的唯一檔案：<content 檔絕對路徑>（<已有 E2E-001 範例，不得改動，在其後依序追加|格式完全比照同夾既有之 <另一流程>.mjs，先讀它當範例>）
- 產製程式（先讀懂驗證邏輯，不要改）：<共用模組與薄殼路徑>
- 內容檔格式：每案例 `{ figs: { 1: '圖名', ... }, text: '敘述', skipImgs: ['圖鍵'] }`；figs 之序號 k 對應 spec 該案例「視覺」段所列圖鍵之順序（略過 skipImgs 者後重新從 1 編號）；text 以 `{fig:k}` 引用第 k 張圖。

## 本流程專屬事項
- <入口：主選單項在可視範圍外，第一張圖為捲動後之畫面，敘述寫「向下捲動至○○並點選」| 無主選單入口，章導文由 config 自訂，敘述不寫「從主選單點選」>
- <暫時狀態之圖鍵清單（上傳中／處理中／鎖定中），敘述寫「上傳進行期間」之畫面>
- <訊息之圖鍵清單；訊息含隨資料變動之筆數者寫「以『○○』起首並接筆數」>
- <零命中或已知落差之案例：敘述以圖為準並明寫該狀態（如「範例僅供了解輸入格式，目前資料無對應者」）>
- <pending 之圖鍵清單或「無」>
- <可照畫面逐字之業務輸入（書目、識別碼）；圖名含英文者改中文語意>

## 工作流程（每個案例都要走完）
1. 讀 spec 該案例之 title / description / flow（含操作、驗證之語意與視覺段、備註）。
2. 以 Read 工具逐張開啟該案例所有標準圖並仔細看（絕不憑檔名或 spec 想像畫面）：紅框框住什麼、畫面上實際出現之彈窗標題、按鈕文字、提示訊息、標籤文字。以 Glob 確認每張圖檔存在；spec 列有但檔案不存在者放入 skipImgs，文中改以文字說明該步結果。
3. 撰寫 figs 與 text。**每寫完 3 個案例即存檔一次**（看圖佔用大量 context，累積到最後一次寫檔會在 context 被壓縮時整份遺失而重頭讀圖）；主代理會以內容檔大小監看進度，長時間 0 byte 視為停滯。
4. 全部寫完後執行 `node "<genMd 絕對路徑>"` 驗證（檢查每張圖有圖名、末字為「圖」、無英數符號、每張圖恰被引用、無多餘引用、全冊不重名），必須無錯誤結束；提示「尚未撰寫之案例」只含 <另一流程前綴> 者屬正常。不要執行 g.mjs / genFigs.mjs / genDocx.mjs。

## 圖名規則（figs）
- 純中文、8～14 字、末字必為「圖」；不含底線、半形括號、{}、|、英文（畫面上之英文名詞改以中文語意）；不得夾帶案例編號或序號。
- 點擊前之圖以「點選○○圖」命名（○○＝按鈕或項目名），輸入類以「輸入○○圖」，點擊後之圖以結果命名。
- 同案例內、全冊皆不得重複；同一動作多節出現時加語意前置語（另存前／刪除前／確認刪除○○）；瀏覽類與編輯類同冊時各自帶足脈絡。

## 敘述規則（text）
- 基於 spec 之 description 改寫為操作手冊口吻，依操作順序逐步敘述，每一步接「，如{fig:k}所示」（置該子句末），每張圖恰引用一次且依 k 順序；結尾可補一句適用情境或注意事項。一段為原則，過長可用 \n\n 分兩段。
- 確定語氣、使用者視角。畫面元素名稱照畫面實際文字逐字（含半形括號、底線、資料名稱之前綴標記）：選單項目、資料夾、清單列、欄位、標籤、彈窗標題、選單內項目、訊息用「」；可點之按鈕與圖示鈕用【】。
- 承接式前置以使用者語言重述（如「開啟「○○」之抽屜並展開進階功能選單後」）；不得寫「承 E2E-001」「見 2.1 節」「詳如前」。
- 全形標點，英文詞組內部半形；數字與英文兩側空格沿用 spec description 之寫法。
- 禁用：<專案禁詞清單全文：破折號、箭頭、段中粗體、括號過長、段首連接詞、測試用語（本案例／測試／e2e／標準圖／紅框／spec／seed／fixture／斷言）、file:line、元件名、程式名、簡稱、以及裁決表所列詞>。
- 數字：隨種子資料變動之數字（筆數、命中數、列數）不寫；結構性數量可寫；規模數字依總則不以數字呈現；訊息含筆數者「以『○○』起首並接筆數」；檔名含日期者「以○○起首並接日期」。測試輸入值含測試字樣者改中性描述。
- 彈窗標題、按鈕文字、提示訊息照圖與 spec 逐字引用，置於「」內。
- 系統名一律全稱。<編輯類：於各案例首句提一次「具<該操作>權限之使用者」。>
- 敘述內容必須與該張圖實際畫面相符；spec 與圖不符時以圖為準並在回報中列出。連續兩張相同之圖（上一步之結果元素即下一步之目標）各引用一次，不是缺陷。
- 畫面呈現之已知落差：敘述以圖為準並明寫該狀態，不宣稱未驗證之「不受影響」。圖上看得到但 spec 未載之內部識別字串、其他即時數值區之載入前狀態：不著墨，列入回報。

## 守則
- 暫存檔一律放 <專案根>/tmp/；只能修改內容檔；不得刪除或重產任何標準圖；不得改 spec（不符處回報即可）。
- 用 Read/Edit/Write/Glob/Grep 工具處理檔案，不用 cat/heredoc/sed；不用 cd。

## 回報（最後訊息）
1. 已撰寫案例清單與各案例圖數（合計須等於 spec 可用圖數）。
2. skipImgs 清單（預期為 <空|已知 pending>）。
3. spec 與圖不符或畫面有疑義之處（附圖鍵）。
4. genMd 驗證輸出之最後三行。
```

## 2. 派工前主代理必做

- 已用同一版式產出一節樣板並經使用者確認；共用模組與內容檔範例（第一案例）已存在，子代理有可抄之實例。
- 已把 spec 中會進表格之 title／description 過一遍 lint 風險（佔位、箭頭、禁詞、括號過長、測試字樣），先改 spec。
- 標準圖夾與 spec 圖鍵已比對一致；pending、暫時狀態、訊息之圖鍵已知並寫進提示。
- 配額：一個子代理之圖數以約 60 張為上限，超過即依案例區間拆兩個子代理（同一內容檔各寫各的案例區間、各自存檔，最後由主代理合併或以追加方式寫入）。
- 模型：內容撰寫需逐張讀圖與判斷，派高階模型；純機械（抄薄殼、改 config）派低階。

## 3. 監看與停滯處置

- 每隔一段時間查內容檔大小（不讀內容）；正常情形每三案例即成長一次。
- 零成長逾半小時、或子代理連續回報「正在讀圖」而無寫檔：停掉重派，提示明令分批存檔並縮小案例區間。
- 子代理配額或過載中斷：檢查內容檔語法與已寫案例，剩餘由主代理逐張看圖接手（同樣每三案例存檔）。

## 4. 收回驗收表（逐冊）

| 項目 | 判準 |
|---|---|
| 回報四項齊全 | 案例與圖數合計＝spec 可用圖數；skipImgs 只含已知 pending；末三行為 genMd 零錯 |
| 逐案例審稿 | 語氣、「」【】標記、承接前置、無測試用語與禁詞、數字政策、無「不受影響」類未驗證斷言、無無依據收尾句、暫時狀態與零命中案例之敘述正確 |
| 抽圖核對 | 每冊至少抽開 10% 之圖（含每類：點擊前、結果、彈窗、訊息），敘述與畫面相符 |
| 不符清單裁定 | 每條開圖確認後三選一：改 spec（同步測試檔、補〈畫面元素對照〉）／退回 e2e 重產／照圖寫；裁定寫入 spec〈已知落差〉或 L3 |
| 產製 | 主代理統一跑 genFigs → genMd → lint → genDocx；docx 以實體檔與 document.xml 文字節點驗證；spec 改後受影響之冊重產 |
| 回報 | 五段格式；「請裁示」經三問過濾；已裁示者不重提 |
