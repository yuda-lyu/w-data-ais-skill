# 由 e2e 標準圖與 spec 產製使用者操作手冊

**觸發條件**：凡基於 e2e spec 與標準圖產製、修改、審閱操作手冊（含分冊）之任務，本篇整篇入 context 逐項比對後才動工。

**閱讀順序**：本檔 §1～§9 → `references/content-pipeline-contract.md`（管線與內容檔契約、檢核規則、失敗對策）→ `references/dispatch-prompt-template.md`（派工提示骨架與驗收表）。專案若已有手冊之 L3 撰寫原則文件（版式、命名、禁詞、定稿句），該文件優先於本檔之預設值。

## 1. 定位：手冊是標準圖的敘事層，不是另一份 spec

- 手冊之三個真理源各有分工，**不得互抄**：
  1. **spec 案例**（`- **E2E-NNN**` 之 title／description／flow 之視覺段）→ 節標題、操作項目表、各節圖清單，一律由程式解析取得，手冊端不手抄。
  2. **標準圖**（每張恰一個紅框，檔名為 `<流程前綴>-<案例編號>-<序號>-<語意鍵>.png`）→ 圖檔原樣複製進手冊，檔名沿用以便回溯至測試。
  3. **內容檔**（人工撰寫）→ 只寫兩樣東西：每張圖的圖名、每節的圖文敘述；外加 `skipImgs`（spec 列有但現況不產製之圖）。
- 手冊不另截圖、不另抄流程、不解釋測試；讀者是使用者，紅框慣例於各章導文交代一次，內文不再提「紅框」「標準圖」「測試」。
- 前置條件：標準圖已經審圖認可。壞畫面（過場、空白、錯位）不得進手冊；發現即退回 e2e 端重產，不在手冊端用文字圓場。

## 2. 動工前盤查（缺一不可）

1. 讀專案報告總則（文體、稱謂、標點、禁詞與裁決表、產圖版式）與既有 md→docx 管線，手冊沿用同一條，不自造。
2. 讀全部目標 spec（含「畫面元素對照」「已知落差」「spec 規則摘要」段），列出：案例數、已廢止案例、pending 之圖、含佔位或箭頭等會直接進表格之 description。
3. 列標準圖夾之檔案清單並與 spec 視覺段逐鍵比對：多／少／命名不一致者先回 e2e 端處理，不在手冊端遷就。
4. 確認版式契約（§3）與命名規則（§4）是否已有使用者裁定；有則照辦，無則以本檔預設值先產一節交審，再全量。
5. 確認 docx 產製依賴（本機 Word 或轉檔服務）可用；產製期間不得開啟 Word。

## 3. 版式契約（預設值；使用者裁定者優先）

| 元素 | 規則 |
|---|---|
| 報告名 | 「{系統名}之使用者操作手冊{版次}」，封面同名；多系統時一系統一分冊，分冊自成資料夾 `src/`（設定、薄殼、`content/`）與 `report/`（md、docx、`pics/`） |
| 章 | 瀏覽類為「一、瀏覽類」，編輯類為「二、編輯類」；該章無已撰寫案例時整章略過 |
| 節 | 每個重要流程一節「1.k {title}」，依 spec 案例序連續編號，只列已撰寫者；已廢止案例不列 |
| 節首 | 一句「本節之操作項目如{表名}所示。」＋操作項目表：欄目固定「項目編號／項目ID／項目名稱／操作描述」，第一欄不換行。此表為使用者指定版式，即使報告總則規定「兩欄不成表」亦屬例外並登記 |
| 圖文敘述 | 基於 description 改寫為手冊口吻，依操作順序逐步敘述，每一步句末接「，如{圖名}所示」；每張圖恰引用一次且依序；一段為原則，過長分兩段 |
| 圖 | 接續排列於敘述段之後，圖題置圖下，圖與圖之間以空段落分隔（docx 管線會丟純空段落者用專案既有之空段落標記） |
| 導文 | 每章章首一段：本章性質（瀏覽不變動資料／編輯會變動資料）、節之組成、紅框慣例（標示應點選之位置或操作後有反應之區域） |

## 4. 命名規則（使用者多次裁定，違者一律退件）

1. **圖名與表名不得夾帶案例編號、項目ID、階段序號等英數代號**（如「E2E-001-1 …」）。英數代號影響觀感、造成使用者負擔；「可回溯」由圖檔檔名承擔，不由圖名承擔。
2. **圖名純中文、末字必為「圖」**，長度約 8～14 字；不含底線、半形括號、`{}`、`|`；固有名詞（資料編號、Excel）例外但盡量避免。點擊前之圖以「點選○○圖」命名（○○＝按鈕或項目名），點擊後之圖以結果命名（「彈窗一般尺寸顯示圖」「儲存成功訊息圖」）。
3. **全冊唯一靠語意前置語**：同一動作在多節出現時加脈絡（「另存前點選開啟選單圖」「刪除前點選開啟選單圖」「確認刪除計畫圖」），不加序號。自動編號機制以名稱為鍵，重名即誤引，產製程式須在重名時拋錯。
4. **表名＝「{項目名稱}之操作項目表」**，帶「之」。瀏覽與編輯同冊時案例編號會重複（兩章都有 E2E-001），故表名以 title 區分，title 全冊不得重複；重複時先改 spec 之 title（同步改 e2e 測試檔之 title），不在表名湊代號。
5. spec 之 title／description 會直接進表格：含 `{佔位}`（會被自動編號機制當引用）、「→」、括號內容超過禁詞表上限、禁詞者，一律改 spec（與測試檔同步），不在手冊端改寫表格內容。

## 5. 產製管線（設計要點；契約細節見 reference）

- 一個共用模組提供 `mkManual(呼叫端位置, config)`，回傳 `genFigs`（複製標準圖）／`genMd`／`genDocx`／`run`；各分冊只剩 `config`（系統名、版次、各章對應之 spec、導文）＋薄殼＋`content/<流程>.mjs`。新增分冊＝抄薄殼改 config、寫 content。
- `parseSpec` 只認結構：案例以 `- **E2E-NNN**` 起始，head 後帶文字者視為已廢止；視覺段內以反引號標示、以該案例 head 開頭者為圖鍵，依出現順序去重。缺 title／description／流程前綴即拋錯。
- `genMd` 之檢核一律**拋錯不警告**：每張圖有圖名、末字為「圖」、無英數符號；figs 數量＝spec 可用圖數；每張圖恰被引用一次、無多餘引用；圖名與表名全冊唯一；content 之案例在 spec 內存在；已撰寫案例缺圖檔即拋錯（未撰寫者略過並提示）。
- `skipImgs` 只用於「spec 列有但現況不產製」（如已知缺陷 pending）；略過後其餘圖從 1 重新編號，敘述改以文字交代該步結果，不引用不存在之圖；缺陷修復補圖後移除。
- 圖檔沿用標準圖原檔名複製到 `report/pics/`；標準圖重產後重跑 `genFigs` 即同步，md 不必改。
- lint（禁詞、data 消費矩陣等）之掃描範圍要納入分冊子夾；新裁定之放行詞（畫面上的資料項名稱）同時登記於禁詞表與 lint。

## 6. 撰寫流程與規則（每個案例都走完，不跳步）

**每案例六步**：①讀 spec 該案例之 title／description／flow（操作、驗證語意、視覺段、備註）→ ②**逐張以看圖工具開啟該案例全部標準圖**，記下紅框框住什麼、畫面實際出現之彈窗標題、按鈕文字、提示訊息、標籤文字；以檔案工具確認每張圖存在 → ③寫 figs → ④寫 text → ⑤跑 genMd 至零錯 → ⑥回報 spec 與圖不符處（附圖鍵）。

**絕不憑檔名或 spec 想像畫面**。敘述必須與該張圖實際畫面相符：spec 與圖不符時**以圖為準**撰寫，並列入回報供主代理裁定是改 spec 還是重產圖。典型不符：spec 說「右上」實為「左上」；spec 說「兩列」實為「一列下展開兩個版次子列」；spec 稱「整個彈窗」實框「內容區」；spec 未載之軸標題、篩選標記、額外欄位；畫面標題被截斷（採 spec 完整名）。

**敘述規則**：
- 使用者視角、確定語氣；全形標點，英文詞組內部半形。
- 畫面元素名稱照畫面文字逐字（含半形括號、底線、「[測試]」前綴；選單名照選單定義之實際文字）；「」表選單項目、資料夾、清單列、欄位、標籤、彈窗標題、選單內項目與訊息；【】表可點之按鈕與圖示鈕。
- 承接式前置以使用者語言重述（「開啟「○○」之資料抽屜並展開進階功能選單後」），不寫「承 E2E-001」「見 2.1 節」「詳如前」。
- 隨種子資料變動之數字（筆數、命中數）不寫；結構性數量（三個資料夾、兩個版次、四顆按鈕）可寫。
- 測試輸入值含測試字樣者改中性描述（「本次之變更原因」「修改後的名稱」）；成功訊息含測試資料編號者改以「以『已新增○○』起首並接資料編號與版次之訊息」表述。
- 不寫測試用語（本案例、e2e、標準圖、紅框、spec、seed）、程式名、元件名、`file:line`；禁詞依專案裁決表（破折號、箭頭、段中粗體、段首連接詞、括號過長、簡稱等）。
- 系統名一律全稱；查詢功能用語依專案之查詢能力定義（簡易關鍵字查詢 ≠ 全文查詢）。
- 下載類流程無點擊後之圖：說明下載由瀏覽器接管與檔名格式即可。編輯類於各案例首句提一次「具編輯權限之使用者」。
- 畫面呈現之已知落差（刪除後畫面未即時更新、關鍵字過濾時右側無有效資料）：敘述以圖為準並明寫更新時機或狀態，避免使用者誤以為操作失敗；不宣稱未經驗證之「不受影響」。
- 圖上看得到但 spec 未載之內部識別字串、驗證提示等：不著墨，列入回報。

## 7. 派工與審稿

- **主代理先做一節樣板**（含管線、config、content 之第一案例）交使用者看版式，再全量；版式裁定後才派工。
- 派工粒度：一個流程（一份 spec）一個子代理，瀏覽與編輯可平行；同系統多子代理寫同一冊時各寫各的 content 檔，genMd 提示「尚未撰寫之案例」含對方流程者屬正常。
- 派工提示必含：絕對路徑、真理源順序、唯一可改之檔案、內容檔格式與 `{fig:k}` 契約、每案例六步、圖名與敘述規則全文、禁詞清單、驗證指令與零錯判準、回報四項（案例與圖數／skipImgs／spec 與圖不符／驗證輸出末三行）；模板見 reference。
- **收回驗收**：逐案例審稿（語氣、標記、禁詞、承接前置、數字）、抽開若干張圖核對敘述與畫面相符、刪掉無依據之收尾句與未驗證之斷言；子代理列的「spec 與圖不符」逐條開圖確認再裁定（改 spec／重產圖／照圖寫）。
- 子代理因配額（429／週限額）或過載（529）中斷：檢查內容檔語法與已寫案例，未寫者由主代理逐張看圖接手撰寫，不等配額恢復。
- 主代理自己撰寫時同樣走六步；多冊接續撰寫時每冊完成即跑 genMd 與 lint，不累積到最後。

## 8. 交付驗證與回報

1. `genMd` 零錯、無「尚未撰寫之案例」提示（除刻意分批）。
2. lint PASS；為過 lint 而改 spec 之 title／description 時，e2e 測試檔之 title 同步改並通過語法檢查。
3. docx 以**實體檔時間戳與大小**驗證，不憑回傳值；解壓抽 `word/document.xml` 核對圖題、表題編號連續、交叉引用全數解析為「如圖N所示」「如表N所示」、無 `{}` 殘留、不換行欄生效；內嵌媒體數少於圖數屬轉檔器對相同圖檔去重，版面不受影響，回報時說明。
4. 回報格式：產出路徑與節／圖數；為過 lint 動到之 spec 與測試檔；**請使用者裁示或知悉之清單**（紅框在同色按鈕上不可辨、圖內測試字樣、畫面英文文案、pending 之圖、版控排除等），不自作主張處置這些屬業主層次的取捨。
5. 使用者要求「先暫停、先看 docx」時：列出已可確認之冊與其節／圖數，停止產製，背景撰寫可續但不產 docx。

## 9. 陷阱與對策（皆已實際踩過）

| 陷阱 | 對策 |
|---|---|
| 圖名帶案例編號「E2E-001-1」求唯一 | 使用者退件；改語意前置語，程式重名拋錯 |
| 瀏覽與編輯同冊，表名「E2E-001 操作項目表」重複致編號錯亂 | 表名改「{title}之操作項目表」，title 全冊唯一 |
| description 含 `{佔位}` 進表格被自動編號機制吃掉 | 改 spec 為描述句 |
| 兩欄表違反報告總則 | 使用者指定版式為例外，登記於 L3 與總則 |
| 子代理憑檔名寫敘述 | 提示明令逐張開圖；驗收抽圖核對；發現即退件重寫該案例 |
| 敘述寫入 390 筆等種子數字 | 改「資料筆數更新」；結構性數量才可寫 |
| 「回復」「全文檢索」「版本控制」等禁詞由 spec 帶入 | 改 spec 與測試檔；lint 放行清單只收畫面上的資料項名稱 |
| 紅框畫在紅色按鈕上幾乎不可辨 | 屬 e2e 端全域改動（框色或外框），列入裁示清單，不在手冊端遮掩 |
| pending 之圖 | `skipImgs` 略過並以文字交代結果；修復後補圖移除 |
| 轉檔服務斷線、docx 假成功 | 以實體檔驗證；有本機 Word 則走本機轉檔 |
| 子代理撞配額中斷 | 主代理接手逐張看圖撰寫，不等待 |
