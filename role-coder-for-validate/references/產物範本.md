# 產物範本（程式驗證）

每一層檢查都必須留下下列其中一種產物；產物放在 `./tmp/`（或使用者指定的專案 docs 目錄）。欄位可以增加，不可以減少；**表上不可以有空白格**——填不出來就是那一格還沒驗證，判定欄寫「未證」。

範例列分兩種：標「實際」的引用取自實際安裝的 `w-dispatch-ai` 1.0.19、`wsemi` 1.8.80（`node_modules/`）與 Codex CLI 0.149.0，2026-08-30 核對；標「示意」的是為了示範格式而設的任務內容，不是任一系統的實作。

## 0. 六問卡（每項檢查執行前填一張）

```
檢查名稱：
1. 檢查什麼：
2. 建置成本：
3. 誰執行：（確定性／AI／人／組合）
4. 實際證明了什麼：（只寫真的能證明的）
5. 產物：（檔名）
6. 工具：
```

## 6. 覆蓋聲明（回報末尾必附）

```
驗證覆蓋
- L0a 可編譯：已做／未做（原因）／不適用（理由）
- L0b Lint：…
- L0c 安全依賴：…
- L0d 實體存在：…（N 項，產物路徑）
- L1 單元：…（通過數／總數；新增測試對應的需求編號）
- L2 整合：…
- L3 代表性資料：…
- L4 效能：…
- L5 E2E／使用者視角：…（表格數、實操數、發現）
- L6 影子運行：…
需求矩陣：已證 a／未證 b／刻意不做 c（產物路徑）
```

每層狀態只有：已做（附統計與產物路徑）／未做（附原因與待辦）／不適用（附理由）。
