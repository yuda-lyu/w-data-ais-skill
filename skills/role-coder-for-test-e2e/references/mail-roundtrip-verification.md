# 信件往返驗證（email round-trip）：以真實收件匣把「只寫進信裡的東西」接回 e2e

**適用**：產品流程的下一步只能從信件取得輸入（重設後的亂數密碼、驗證連結的識別碼、一次性登入碼），或 spec 要求信件的寄件者／主旨／內文逐字相符、且手冊要呈現「收到的信長什麼樣」。本篇是 SKILL.md §10「email round-trip」列的展開；專案落地（收件匣清單、金鑰檔位置、案例編號、模板路徑）寫在該專案的規則帳本與共用文件，不寫在這裡。

**順序**：§1 盤點寄信點與三步探測 → §2 收件匣 → §3 後端與時鐘 → §4 取信與斷言 → §5 模板與標準圖 → §6 自助註冊 → §7 改版時的三處同步 → §8 勾選。

## 1. 先盤點全部寄信點、證明三步可行，再擴案例

- **盤點寄信點**：grep 產品之寄信呼叫（`sendMail` 類）與設定檔之信件鍵（主旨、內文模板），列表：觸發操作／收信者／主旨／內文置換值／是否有後續結果頁（驗證成功、已驗證、無效連結）。**每個寄信點至少一個收信案例**，結果頁每個終態各一個可觀察案例。只做最先想到的那一種信（管理者重設密碼），變更密碼通知與註冊驗證信就會被使用者反問「其他模板為何沒有標準圖」。
- **三步探測**：動手擴 spec 前先各做一次最小探測並留 log：①以 API 建立或列出收件匣；②用產品現行寄信功能寄一封到該收件匣；③以 API 讀回全文並取出要用的值（密碼、連結）。任一步不通就回報，不先寫案例。殷鑑：第一把金鑰對 API 與儀表板皆回 `Forbidden`，探測一分鐘就發現，省掉整批案例白寫。
- 探測時順手抓一封信的**原始 HTML** 回來看：收件匣服務存下的 HTML 與寄出的不同（§5），版式與斷言都要以存下的那份為準。

## 2. 收件匣服務的選擇與配置

- **要 API 可讀全文**：組織層金鑰能列收件匣、讀信件 html/text、建收件匣；只能寄不能收的服務不適用。儀表板多為 OAuth 登入，不可自動化，也不拿它截圖。
- **一位收信者一個收件匣**：以收件匣名對應種子帳號（`{帳號小寫}@…`），display name 用該帳號的顯示名，信件內文的稱呼才對得上。
- **免費方案有每帳號收件匣上限**：不夠時再要一個服務帳號，金鑰檔改成「預設金鑰＋收件匣→金鑰對應表」，取信時依收件匣挑金鑰。子位址（`+`）能省收件匣，但先確認產品的電子郵件檢核放行 `+`，否則種子含 `+` 會讓整張使用者清單每次儲存被擋。
- **金鑰檔**：`test/e2e-secrets.json`（gitignore）＋同構範本 `e2e-secrets.example.json`；缺檔或金鑰無效時涉信案例**直接拋錯**，不 skip、不 pending——靜默略過會讓「收信」這段永遠沒被驗過而測試照綠。
- **種子**：收信者的電子郵件改為收件匣位址。若專案慣例是「密碼即電子郵件」而某帳號的密碼是跨專案共用的標準測試密碼，種子產生器加密碼覆寫表讓密碼不變，並在共用文件記為唯一例外。改種子後先 grep 舊值於全部測試檔、共用模組、spec 與手冊內容檔（§7），並刪掉 e2e 之資料庫快照（快照存在時重置直接複製快照，種子改動不會生效）。

## 3. 後端與時鐘

- 涉信案例標 `mail: true`，重置時以真實 SMTP 啟動後端；其餘案例的 SMTP 一律指向拒絕連線的埠（`127.0.0.1:1`），確保只有該等案例會外寄。
- **假時鐘會讓信送不到**：寄信程式庫以無參數 `new Date()` 產 Date 標頭，假時鐘使標頭落在過去，SMTP 回 `250 OK` 但收件匣永遠不出現。在 e2e 後端殼對 `sendMail` 補 `date: new Date(Date.now())`（`Date.now` 未被攔截），不動產品碼。「SMTP 接受」不等於「送達」，寄後一律以收件匣輪詢確認。
- 每次全跑會外寄幾封、月配額多少，寫進規則帳本；信件不刪（收件匣即證據），取信以時間與訊息識別碼過濾。

## 4. 取信與斷言

- `waitMail({ inbox, subject, since, excludeIds })`：每 3 秒輪詢，取主旨相符、時間戳不早於案例起始減 60 秒、且不在 `excludeIds` 內的最新一封，讀全文；120 秒逾時拋錯。
- **同案例同主旨兩封**（申請時一封、重寄一封）：動作前先列既有訊息識別碼，取信時排除，否則抓到第一封而假通過。
- **內文比對用逐行純文字，不比原始 HTML**：html → 去註解、`<br>` 與區塊結尾（`p`／`div`／`td`／`tr`／`table`／`h1～h6`／`li`）換行、去標籤、還原實體、逐行 trim、去空行；spec〈信件對照〉以「⏎」列逐行內文，測試之期望文字逐行相同。比原始 HTML 會被收件匣服務之屬性剝除與版式微調弄紅，而那些都不是使用者看得到的差異。
- 寄件者、收件者、主旨逐字；隨機部分（密碼、識別碼）以格式斷言並抽出供下一步使用。
- 連結類：斷言起首與結尾（基底網址、`token=`、語系參數），開啟後的結果頁（成功／已驗證／無效）各是一個可觀察終態，各自一張圖，內文以逐行純文字斷言（系統名、寄件者名、訊息原文、頁尾）；「無效連結」是不需要收信的瀏覽類案例。

## 5. 信件模板與標準圖

- **模板是產品的一部分，先給使用者看設計稿再套用**：設計稿（含範例值之預覽圖）放暫存區交審；業主常見要求——**點名所屬系統**（主旨前綴「【系統名】」、標頭大字、頁尾「本信件由○○之「△△」寄出」），因同一登入套件會部署於多套系統，收信者要分得出是哪一套；HTML 卡片版式、全 inline style、無外部圖片；置換值經 HTML 跳脫。
- **收件匣服務存下的 HTML 會剝除屬性**（`width`／`cellpadding`／`align`／`role` 與 HTML 註解，只留 `style` 與 `href`）：版面屬性一律同時寫進 `style`（`width:100%`、`margin:0 auto`、`border-spacing:0`、間隔列 `padding:0`），屬性照留給一般信箱；殷鑑：第一版模板外層表格因此縮成內容寬、卡片靠左。
- **檢視器頁**：不截儀表板。以固定版式的檢視器頁在同一 context 另開一頁 `setContent`：收件匣、主旨、寄件者、收件者、內文；**不顯示時間**。紅框框內文整塊。版面留白要能容納最長的一封（含帳號與密碼框之重設信），否則全頁截圖仍會裁到底部。
- 隨機字串換成固定寬度的黑條，讓像素決定性且不洩漏：`<strong>` 內的亂數密碼換 120px 黑條；連結內 `token=` 的值換 220px 黑條並移除 `href`（保留可讀的基底網址與語系參數，讀者看得出這是連結）。
- 手冊敘述寫「隨後於信箱收到寄件者為「…」、主旨為…的信，信中…」，不提收件匣服務名稱；主旨含專案內文規則禁用之標點（「【系統名】」前綴）時寫「主旨為「密碼已進行變更」並冠以系統名「○○」」，spec description 同法。

## 6. 自助註冊類流程的額外事項

- 需要設定開關（允許註冊、驗證連結的基底網址）：各環境設定同步，e2e 設定自正式設定衍生，登入頁自此多出「申請帳號」類連結——凡拍到登入區塊的既有標準圖都受影響，依 §7.9 只重產受影響者並以雜湊回驗其餘未變。
- 自助建立的帳號常缺「登入後轉址」等後台才填的欄位，預設登入會被擋：案例改走不需要該欄位的入口（如使用者資訊頁），並在 spec〈已知落差〉記為設計事實，不改產品。
- 節流（同帳號 N 秒內只能重寄一次）與「申請不記節流」這類細節先讀後端證成，寫進 flow 備註，避免案例順序踩到節流。
- 結果頁之三則訊息（成功／已驗證／無效）常在套件語彙檔而部署端無設定鍵可覆寫：業主要改字時先寫建議檔（擴充：加設定鍵），升版後才改三處（§7）。

## 7. 模板或文案改版：三處同步與重產範圍

- **三處同步**：模板檔（或設定之主旨鍵）、spec〈信件對照〉、測試之期望文字（主旨常數與逐行內文）。改任一處先 grep 舊主旨與舊句子於 `test/`、`spec/`、手冊 `content/`，全部改完再啟動重產鏈；殷鑑：帳號電子郵件改為收件匣後只改了編輯冊之常數，瀏覽冊之常數與 spec 語意句仍為舊值，全量重產跑到中段才以語意斷言失敗。
- **只能由套件改的文案**（語彙檔內、部署端無設定鍵）：寫建議檔請套件加設定鍵；套件發布後 registry 約數分鐘才可見，輪詢 `dist-tags` 後重裝、以全新頁面實測生效，再改三處。改版期間 spec 之訊息先寫現況、備註載明待套件升版。
- **重產範圍**：只重產含信件與結果頁之圖（以案例清單 gate），其餘以雜湊回驗未變；〈已知落差〉記「事實更正（業主裁定 YYYY-MM-DD）」並列重產之圖鍵。
- 交審以圖文對照之審圖報告（SKILL §7.6）；手冊之圖名、敘述與 docx 同輪更新。

## 8. 勾選

- [ ] 三步探測 log 在案；金鑰缺失即拋錯；已看過收件匣存下之原始 HTML
- [ ] 一收信者一收件匣；多帳號時金鑰對應表；種子密碼例外已記；改種子已 grep 全部常數並刪快照
- [ ] `mail: true` 案例才用真實 SMTP；Date 標頭墊片；配額與封數已記
- [ ] 同主旨多封以識別碼排除；斷言以逐行純文字對〈信件對照〉
- [ ] 模板點名所屬系統、版面寫在 style；信件圖為檢視器頁、無時間、隨機字串黑條、容納最長信；結果頁各一張
- [ ] 改版時模板／〈信件對照〉／測試期望三處一致；只重產受影響之圖並雜湊回驗；手冊同輪更新
