# 既有系統 UI 重新設計紀律

**觸發詞**(出現任一,一律當[整體重做]處理,不可降級成[調樣式]):「重新設計」「重做」「redesign」「要有設計過 / 設計感」,以及任何對美感 / 版面 / 比例 / 對齊 / 留白 / 風格的不滿.

**定位**:本技能管[改造既有 production 系統之 UI]——量測既有版面、盤點不可變資產、遷就既有組件庫與設計語言.從零產出獨立靜態 Web 產物(landing page / 簡報 / 儀表板原型)不適用本技能,改用 role-design-web-for-prototype 系技能;其中純美學通識(避開 AI 味、icon 選用優先序、placeholder 哲學)可另參 role-design-web-for-prototype 之[設計原則]節.

## 進入後交付前必做,且一次做完(不逐點等使用者挑錯)

1. **讀完該元件 / 組件完整 API 與所有 prop 預設值**——陰影 / 邊框類預設常為 `true`,沒讀就會踩到(殷鑑:`WButtonChip` 的 `shadow` 預設 true,沒看到就多了不搭的投影).
2. **量測實際版面數字**——尺寸 / 間距 / 對齊 / 比例,用 `getBoundingClientRect`(可經 w-screenctl `/chrome/evaluate`)取真值,找根因並用數字佐證,不憑肉眼猜.
3. **盤點周邊設計語言**——色票 / 圓角 / 間距節奏 / 既有同類元件樣式,沿用求一致.
4. **提 ≥2 個設計方向,擇一並說取捨**,不直接微調現況.
5. **從整體決定**層級 / 比例 / 對齊 / 留白 / 動態,而非逐一 prop.
6. **一次交付完整設計 + 理由**,自行截圖驗證 resting / hover 等各狀態.
7. **盤點不可變資產與上游產物**:後端預產圖檔(底色/尺寸/內含標題)、API 產物格式、字型等——先實際抓一份樣本打開看,設計必須遷就,不可憑假設選色系(殷鑑:frliq 監測頁後端產圖為白底,首輪重設計卻做深色系全滅).
8. **梳理資訊架構綁定關係**:動筆前把[選單-內容-附屬功能(搜尋/清單)]的歸屬與觸發鏈寫成清單(誰綁誰、點了切到哪、預設停在哪);版型可變、操作語意不可變,要變須先報備並經使用者同意(殷鑑:frliq 地震事件搜尋樹綁定於地震事件選單,首輪設計拆成常駐側欄/水平帶被退).
9. **RWD 是交付的一部分,且是逐區塊的設計而非只做抽屜顯隱**:各斷點行為(顯隱鈕、抽屜浮動/收合、控制列摺疊)須設計且可實測;缺 RWD 之設計視為未完成(殷鑑:frliq 首輪 5 版全數未設計顯隱抽屜被退).**每個區塊都要問[窄版時它變成什麼樣?]**,禁止放任 flex-wrap 自動往下疊交差:①資訊磁貼/按鈕帶→窄版改單列橫向捲動或壓縮款式,header 不得吃掉過半可視高(比例原則:內容展示區永遠是主角);②工具列/選單列→縮 padding 與字級,右端狀態元素(倒數/計數)須 `flex:0 0 auto` 保證可見,不可被擠出;③內容區 padding 須與版面連動——窄版空間已少,水平 padding 要縮小讓內容(圖/表)展示最大化,寫死大 padding=沒設計;④交付前以窄版實寬截圖逐區檢查高度比例與可見性(殷鑑:frliq monitor 頁首磁貼窄版直落疊半屏.倒數被擠出.padding 不連動,被評[隨便亂設計亂排就交差]).
10. **換位置≠重新設計,沿用原展示語言≠重新設計**:把既有元素搬個位置(功能列上移/下移)、沿用原系統的高亮語言(如左緣 border 高亮)、沿用原本的區塊切分,都只是[配合原本的設計].重新設計的界線:**操作功能與流程(語意層)記好不可變,其餘版面/區塊切分/展示手法/視覺語言全部重新想**;交付前逐區自問[這一區的呈現手法是重新設計的,還是搬來的?]搬來的比例過高＝沒設計(殷鑑:frliq R4 選單高亮沿用左 border、功能列只是換位置被退).
11. **資訊匯總≠設計:數據區塊必須有展示設計**:把 label+粗體數字丟進區塊只是[把資訊匯總過來放],不是設計.數值/狀態類資訊帶動工前須**上網調研業界數據展示實例**(dashboard stat card / KPI tile / sparkline 迷你趨勢 / gauge 量規 / 語意 icon / 趨勢箭頭 / 色彩語意),為每類數據選擇適配的視覺化形式並說明參考來源(殷鑑:frliq R4 監測通道 panel 僅文字+粗體數字被評[這哪叫設計]).與全域規範 §9.5 相輔:§9.5 管型別錯配,本條管[型別對了但零視覺設計].
12. **資訊權重與關聯性決定擺位**:每個元素先問[它屬於哪個資訊群?與誰一起被閱讀?]附屬資訊須緊鄰其所屬群組——如測站告示圖屬測站資訊,應與站名相鄰成[圖配文],不可因[右上角剛好有空間]把它放到設定/使用者資訊慣用區.版面慣性(右上=設定,右側=次要)會誤導擺位,以資訊關聯性優先(殷鑑:frliq R4 告示圖被擺到右側像設定鈕被退).同性質元素同區歸位:摘要卡(如最新事件)與 meta 群同排;狀態文字(如刷新倒數)歸入導覽/工具帶置右,不散落各處(殷鑑:frliq R7 被要求併區).
13. **icon 語彙是重新設計的一部分**:調研參考範本時同步萃取其 icon 用法;meta chips/導覽項/分類標籤等資訊元素應配可辨識之 icon(inline SVG,非 emoji,語意對應:座標=定位針,波形=地震…).查了一堆參考卻交出純文字 chips＝調研成果沒帶回設計(殷鑑:frliq R6 座標/鑽孔/地震事件 chips 純文字,被質問[查了這麼多資料 icon 都沒有?不可能吧]).
14. **資料驅動元素須生成式設計＋邊界處理**:數量由資料決定的元素(感測器 n 支,欄位 n 個)必須實證資料結構後以資料生成,並處理 n 變化之邊界(標籤/按鈕防重疊,最小與最大 n 之版面);寫死示例數量＝沒抓到業務結構(殷鑑:frliq 水壓計每站 1~3 支,R5 前一直畫成 1 支;深度導航被要求支援多水壓計+防重疊).
15. **側欄/導航面板之 RWD 一律沿用系統既有抽屜慣例**:新設計的任何側欄(導航,清單,面板)比照主系統抽屜模式——寬版可收合(如 30px 軌條+顯隱鈕),窄版浮動覆蓋+遮罩+顯隱鈕;每加一個側欄都自問[窄版怎麼辦?](殷鑑:frliq 深度導航首版窄版直接 display:none 被要求改抽屜).互動導航點擊須有回饋動畫(如平滑捲動),不可瞬跳.
16. **RWD 五鐵則——斷點是手段,內容實寬才是事實**(殷鑑:frliq monitor 選單列/磁貼帶一日連退四輪,每輪都是打補丁而非整體設計):
    ① **先算後排**:動工前逐項計算內容帶實際總寬(字數×字寬+icon+padding+gap,rem 記得乘 root 字級);內容實寬(如 1060px)大於你設的斷點(660px)時,中間全是災區——優先採與寬度無關之通用結構(固定區+`flex:1; min-width:0`+內部橫捲),讓版面自適應而非猜斷點.且[固定區+flex:1]結構須以**可變文字之最長情境**檢核(站名/地址長短組合):固定區實寬佔比過大時,flex 區會被擠成窄縫還在縫裡開捲軸——剩餘寬低於合理下限即改上下斷行成列,兩者各得全寬(殷鑑:frliq 頁首窄版識別區吃掉大半寬,磁貼帶剩窄縫被批[重要資訊只能用超窄區塊呈現]).
    ② **nowrap 全數列管**:每個 `white-space:nowrap` 都是溢出炸彈,會把整版推移裁切且無捲軸可救;動工前列 nowrap 清單,逐個給[空間不足時的讓位策略](標籤縮短/次要字隱藏/換行),並於捲動容器加 `overflow-x:hidden` 保險.
    ③ **狀態元素永不犧牲**:倒數/計數等狀態元素 `flex:0 0 auto`,被裁到剩[9 分]的倒數＝沒有倒數;空間不足時由主功能群讓位,而讓位手段首選**標籤縮短**(語意不變+tooltip 全名),**禁用[群組內捲動+藏捲軸]於選單類**——內部剪裁會造成[被旁邊元素遮蔽]的假象,比溢出更像壞掉.
    ④ **讓位是設計不是位移**:把元素移位/疊上去/剪一半都不是 RWD;每次調整後自問[各元素在此寬度下是否完整可見.互不遮蔽.比例合理?]
    ⑤ **驗證掃寬度譜**:至少 320/360/430/660±20/768/1024 逐寬量測斷言(單列性,右端元素完整可見且不與鄰元素重疊,`scrollWidth≤clientWidth`);只驗單一寬度＝沒驗(殷鑑:只測 430 一點,331/731 全漏).

## 間距對稱原則

水平與垂直留白不必完全相等,但比例差距不可過大;尤其值小時(如 5px vs 14px)差幾 px 觀感差異就很大,須拉近比例(值大時差幾 px 才不明顯).

## 相輔規則(常駐於全域規範,不因本技能而免除)

- 全域規範 §9.5:展示形式須匹配欄位型別/語義,交付前逐欄自掃.
- 全域規範 §9.6:觸碰既有排版或新增小元件須量數字+盤色票——即使任務被框成[功能搬移/重構]而非[設計],該節義務仍然成立.
