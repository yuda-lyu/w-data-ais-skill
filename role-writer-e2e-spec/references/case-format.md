# E2E-NNN 案例之格式、對照表欄位、範例與檢核

本檔為 SKILL.md §3、§5 之逐欄格式。每個案例以三層 bullet 撰寫，順序固定。

## 1. 骨架

```md
- **E2E-007**
  - title: <使用者觀察視角一句話（以○○為例）>
  - description: <操作手冊敘述，見 §2>
  - flow:
    - 測試資料：<seed 來源；具名對象之編號／顯示文字／版次；登入帳號與權限（引用帳號矩陣）>
    - 操作：<起點> → <動作 1> → <動作 2> → …
    - 驗證：
      1. 語意：<可觀察文字／URL／存在性；實測數字並標明隨種子變動者>
      2. 視覺：`E2E-007-1-click-diff`（框住操作列之「版本差異比對」按鈕整顆）→ `E2E-007-2-diff-all-fields`（框住差異比對彈窗整個面板含標頭）→ …
    - 雙語：<各語系一輪／單一語系省略並於共用文件載明>
    - 清理：<依副作用類型之具體處置與回驗；純瀏覽寫「不變動資料，不需清理」>
    - 備註：<不可達或不可自動化證據、檔案:行號、對稱關係、共用標準圖、測試手段、量測與操作方式>
```

廢止：`- **E2E-008**（已廢止，編號保留不再使用；理由：○○標籤為純顯示不可點，見〈已知落差〉）`。理由固定用語：「不可達」「不可自動化」「現行種子無此權限組合之帳號，待增設後恢復」「情境已因 YYYY-MM-DD 之修復不存在」。

## 2. description 寫法

### 2.1 寫成什麼

- 骨架「在哪裡 → 做什麼 → 看到什麼 → 什麼時候用得上」；二至四句只是建議，以六問為準。
- 入口寫到位置與提示文字：「右側內容區標頭列的「彈窗顯示」按鈕」「左側目錄區上方的加號按鈕，提示文字為「新增○○」」；權限寫明「僅具編輯權限的使用者看得到」；入口在可視範圍外寫「需先於主選單區以滑鼠滾輪往下捲動才點得到」。
- 畫面文字逐字：按鈕名、欄位名、訊息原文（含全形半形、空格、括號）；訊息含變數者以描述句表達，不用 `{}` 佔位。
- 位置詞（左上／右上）、數量詞、捲動結果以最終畫面為準（產圖後對帳）。
- 補充以「此時」「其中」「亦即」展開成句；用途以「便於…」「適合…」「可用於…」。
- 具名對象以「以○○為例」呈現，避免讀成永久產品行為。
- 短暫訊息寫「畫面右上角會顯示訊息「○○」」；停留幾秒不寫（屬 flow）。

### 2.2 六問（答不出任一即不合格）

1. 入口與權限　2. 必要前置　3. 不可逆效果　4. 是否已寫入（或仍需儲存）　5. 成功識別（訊息原文或欄位）　6. 失敗如何處理（被攔截看到什麼、關閉後停在哪、如何重試、找誰調權限）
另附：送出方式（「按 Enter 或點右側圖示」）、可照抄之範例值（網址參數附完整範例與值域）。

### 2.3 不得出現（句型與受眾判準）

| 類別 | 例 |
|---|---|
| 以測試為主語 | 「本案例為…之驗證」「本案例含兩階段截圖」「兩者成對構成契約」 |
| 對撰寫者之指示 | 「撰寫 e2e 時須等待…」「此差異須於 spec 明載」 |
| 程式位置與識別字 | `xxx.vue:406`、組件名、prop、變數、`width<500` |
| 案例交叉引用 | 「與 E2E-003 為同一按鈕之分歧」 |
| 截圖階段 | `stage1`、「第二張圖」 |
| 可改寫成正文之括號夾註 | 「顯示座標軸（尚未載入模型）」→「顯示座標軸，此時尚未載入模型」 |
| Markdown 強調、佔位、箭頭 | `**不勾選**`、`{名稱}`、「→」 |
| 需求對應語 | 「本案例對應…需求」→「可用於…」 |
| 含測試字樣之範例值 | 「輸入 e2e測試說明」→「輸入本次之說明文字」 |

不禁止：產品名與縮寫、畫面原文中的括號、單位與格式範例、要照字面輸入的參數名、領域詞（「階段」「驗證」作為資料語意時）。

### 2.4 機械掃描

`本案例|驗證使用者|截圖|stage[0-9]|E2E-\d|src/|\*\*|（[^）]{12,}）|\{[^}]*\}|→|e2e|測試(?!範例)` 零命中（「使用測試範例」等畫面原文例外，逐一確認）；掃描抓表面違規，六問抓「刪過頭」，兩者都做；有專案 lint 者對 title／description 一併跑。

### 2.5 用詞統一

恢復（「還原」只用於按鈕原文）；點選（清單、樹狀、選單項目）／點擊（按鈕）；「從主選單點選「○○」後」。

## 3. flow 各 bullet 之保留與丟棄

| 保留（契約） | 丟掉（實作細節） |
|---|---|
| 具名資料之欄位語意值 | helper 函式名 |
| 使用者操作層級（點按鈕、輸入欄位、滾輪於某處） | 框架 API、selector 字面 |
| 應觀察之文字、URL、DOM 終態、幾何（左緣位置、面板寬度） | 固定等待毫秒（改「等待○○完成後」） |
| 標準圖檔名（圖鍵）與框住之元素 | 比對 API 與容差數值 |
| 語系清單 | 內部旗標、常數 |
| 清理範圍、副作用類型與回驗方式 | DB／ORM 字面、後端呼叫鏈 |
| 測試手段之範圍（攔截整個後端主機） | 攔截 API 名 |

`檔案:行號` 在驗證、備註與各對照表是允許且鼓勵的；只有 description 不可出現。

## 4. 視覺項（操作序列）之寫法

- 每個操作兩張：`<序>-click-xxx`／`type-xxx`／`check-xxx`／`scroll-xxx`（框住要點的位置）→ 結果圖（框住有反應的元素）。
- 括號寫到元素：「整顆標籤含前導模式鈕與移除鈕」「整個抽屜面板含標頭」「目錄樹當時完整可見之全部節點列」「差異表格」「成功訊息整顆」；不寫「框住區域」「框住右欄」「框住畫面」。
- 一張圖只一個框；目標被彈窗或遮罩蓋住：「框住彈窗，原目標位於彈窗之後不框」。
- 大面積容器內只有部分內容：框「當時可見之內容聯集」而非整個容器（避免框到大片空白）。
- **入口在可視範圍外**：首圖為「滾輪捲動後，框住主選單之該項整列」。
- **短暫訊息**：「框住訊息「○○」整顆」；其下一張非訊息之圖註明「訊息淡出後」；訊息時機寫在〈訊息對照〉。
- **暫時狀態**（上傳中、處理中、鎖定中）：圖鍵後加「（暫時狀態，不列入比對；框住…）」，共用文件登記此類圖之比對政策。
- **連續相同之兩張**：上一步之反應元素恰為下一步之目標（收合後新出現之開啟鈕）時兩張相同，照列不合併。
- **負向變體**：缺值／值不存在／格式不符各一張，結果畫面相同亦各列。
- 產品缺陷步驟：「此圖不產製，e2e 於此步偵測到○○即標 pending，缺陷修復後補產」；修復後改寫為正常結果描述。
- 下載類：至少點擊前一張，寫明「下載由瀏覽器接管，無畫面終態」。
- 同流程首案例寫一次通則：標準圖存放位置與檔名前綴、每步兩張、一圖一框、框實際內容不框空白、訊息與暫時狀態之處理；其餘案例只列序列。
- 畫布類系統：不寫遮罩或填黑，寫共用文件所定之覆蓋比對策略，圖鍵照列。

## 5. 對照表之欄位

### 5.1 畫面元素對照

| 區域 | 元素 | 顯示文字／提示文字 | 圖示 | 定義位置 | 出現條件 | 觸發後行為 |
|---|---|---|---|---|---|---|

「出現條件」寫兩層：狀態（有檔案時、有報告時、恆顯示）× 權限（具○○權限）× 鎖定（處理中不可點／不受鎖定）。手冊撰寫時由圖核對補列之元素（目錄項高亮、篩選標記）加註「（由標準圖核對補列，日期）」。

### 5.2 訊息對照

| 觸發情境 | 訊息文字原文 | 樣式 | 時機 | 定義位置 | 可達性 |
|---|---|---|---|---|---|

樣式：右上提示（自動消失）／確認對話框／內容區文字／輸入框旁提示。時機：在什麼事件之後多久出現、停留多久（實測值）。可達性：可達／UI 不可達（附條件）／需失敗注入（附手段）。

### 5.3 測試資料

| 變體 | 具名對象 | 顯示文字（唯一化） | 版次／筆數 | 取用方式 | 選它的理由 |
|---|---|---|---|---|---|

登入帳號另引用共用文件之帳號矩陣。

## 6. 副作用與清理對照

| 副作用 | 清理 | 回驗 | 可否由資料庫重置回復 |
|---|---|---|---|
| 資料庫資料列 | 快照複製或完整重建 | 以畫面筆數列回到基準值 | 可 |
| 上傳落地之實體檔案 | 案例自行刪除本次產生者，或完整重建含目錄 | 目錄內無本輪時間戳之檔案 | 否 |
| 伺服器暫存與批次資料夾 | 呼叫清空作業 | 目錄為空 | 否 |
| 後端於既定資料夾以外寫出之檔案（除錯輸出、錯誤紀錄） | 案例結束刪除；同時列〈已知落差〉待裁示其歸屬 | 該路徑無殘留 | 否 |
| 使用者下載之檔案 | 案例結束後刪除 | — | 不適用 |
| 原始碼目錄之產生檔 | 不可於主工作樹執行；於可拋棄副本或 API 層驗證 | — | 否 |
| 剪貼簿 | 不需清理；下一案例 fresh context | — | 不適用 |

## 7. 已知落差之條目格式

`- **<一句話標題>（<分類>；<日期>）**：<症狀與證據（檔案:行號 或 探測 log 檔名＋時間）>。使用者可觀察之後果：<…>。<處置或修復紀錄>。`

分類四選一：缺陷（待修）／設計事實（記錄備查）／待裁示（業主決定）／已修復（附修復紀錄）。權限相關者於症狀句標明軸別。spec 自身原載不成立者：「本 spec 原載『…』不成立：實測…（見 E2E-NNN）」。

## 8. 跨案例連結（只寫在 flow 與備註）

- 共用標準圖：驗證 bullet 檔名後註「與 E2E-XXX 共用，不另設標準圖」；description 不提。
- 對稱關係：備註寫「與 E2E-XXX 為對稱路徑」，供盤查漏格。
- 只引本文件內之案例，不引其他流程文件。

## 9. 寫完前自問

1. title 是使用者觀察視角且過四限制？
2. description 六問答得出、機械掃描零命中、畫面文字與程式碼逐字相符、位置詞數量詞已與圖對帳？
3. flow 每案自述前置、數字皆實測、清理寫到副作用類型與回驗、備註承接了 description 拿掉的技術資訊？
4. 每條操作路徑已對照 `v-if` 確認可達；可自動化性已查；權限負向已先滿足狀態條件且標軸別、帳號存在？
5. 〈測試資料〉依型別、內容、入口各列一筆且為最豐富者？
6. 視覺項每步兩張、括號到元素、訊息與暫時狀態已標、通則只寫一次？
7. 未引任何舊版文件或草稿；已知落差每條附證據、日期與分類？
